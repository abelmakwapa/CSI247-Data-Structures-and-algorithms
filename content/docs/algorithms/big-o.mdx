## Definition and intuition

<AcademicPanel tone="definition" title="A language for growth">
Big O describes how a resource grows with input size while ignoring constant factors and lower-order detail. Name the input variable, resource, case, and assumptions.
</AcademicPanel>

## The problem it solves

Complexity analysis lets you compare approaches, anticipate scale, and explain why an algorithm fits—or fails—the constraints.

## Real-world analogy

A fixed five-second setup matters less than whether the work doubles, grows linearly, or explodes when the input doubles.

## Trade-offs

- Growth rates make scalability explicit and help compare time against memory.
- One letter can hide multiple input dimensions, and average, worst-case, and amortized stories can differ.

## Common mistakes

<AcademicPanel tone="warning" title="Count the dominant work">
Sequential blocks add, nested work multiplies, and a halving process is logarithmic. Then state auxiliary space separately from input storage.
</AcademicPanel>
