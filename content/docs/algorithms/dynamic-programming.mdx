## Definition and intuition

<AcademicPanel tone="definition" title="State first, transition second">
Dynamic programming combines optimal substructure with overlapping subproblems. Define a state, base cases, and a transition, then compute each state once top-down or bottom-up.
</AcademicPanel>

## The problem it solves

DP handles knapsack, edit distance, grid paths, sequence problems, and recursive searches that repeat the same state.

## Real-world analogy

Write down the best route to each smaller destination so later routes reuse those answers instead of walking the same streets again.

## Trade-offs

- Memoization removes repeated work and bottom-up tables make dependency order explicit.
- State design is harder than the final loop, and the table may consume substantial memory.

## Common mistakes

<AcademicPanel tone="warning" title="A table is not a state definition">
Explain what one cell means in a full sentence before writing the transition. Otherwise it is easy to compute the wrong answer efficiently.
</AcademicPanel>

## Interview questions

- What are the state, base cases, and transition?
- Is memoization or tabulation more natural here?
- Can the table be space-compressed, and do you need reconstruction?
