## Definition and intuition

<AcademicPanel tone="definition" title="Mental model">
A trie stores strings by walking one edge per character. Words with the same prefix share the same path, so autocomplete can jump to a prefix in O(k), where k is the number of typed characters.
</AcademicPanel>

<AcademicPanel tone="theorem" title="Remember this">
Hash maps find exact words; tries find words that begin the same way.
</AcademicPanel>

## The problem it solves

Reach for a trie when prefixes, autocomplete, or lexicographic traversal matter.

### Where it appears

- autocomplete
- spellcheck
- IP routing
- dictionaries

## Real-world analogy

<AcademicPanel tone="pro" title="Autocomplete">
Type “app” and the search engine follows three shared letter edges before exploring only the matching branch.
</AcademicPanel>

## Trade-offs

### Strengths

- Prefix lookup is direct
- Shared prefixes reduce repeated work

### Watch-outs

- High memory overhead
- Not ideal for arbitrary non-string keys

## Common mistakes

<AcademicPanel tone="warning" title="Pressure-test the trade-off">
Hash maps find exact words; tries find words that begin the same way. When the workload changes, revisit whether the structure's invariant still matches the problem.
</AcademicPanel>

## Interview lens

### What a strong answer notices

- Define k and z before stating prefix complexity.
- Terminal markers distinguish “app” from the longer word “apple.”
- Compressed tries trade implementation complexity for space.

### Questions worth rehearsing

- Why can a hash map not answer prefix queries directly?
- What does a terminal marker mean?
